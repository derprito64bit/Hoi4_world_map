## 13. P00b-f3: EXP-03-24k crash root cause (4c0388f, pending review)
**Cause (from both 24k minidumps, `crashes/hoi4_20260929_073046` and `…_074145`):** integer divide-by-zero in the strategic-region centre computation (`strategicregiontemplate.cpp`, assert "IsRegionCenterSet() && Calculations where incorrect"), `idiv ecx` with ecx = 0 at hoi4.exe+0x15A4CDC.
- The engine takes the integer mean of member province bbox centres (y from the bottom, box w/h = span+1). If that mean point lies in no member box, it falls back to a line march from the region rectangle's centre and divides by `mean.x − (rx0 + rw/2)` (rw = span+2) without a zero check.
- In 24k, region **191 Northern Norway** (54 provinces): mean (3141, 1961), rect (2990, 1854, 302, 170) → 3141 − (2990 + 151) = 0.
- Region 191's divisor: vanilla −10, 16k −10, 20k −11, **24k 0**, 30k +2 → 24k hit 0 by chance; the province count is not the cause.
- The offline model `tools/experiments/regioncentre.py` reproduces the dump. It flags only 24k among the builds; every build that loaded in game has 0 *unsafe* regions; EXP-02-300 and -1200 each have one new seam/unknown region (95, 97) and loaded, which is weak evidence that seam regions are handled. Vanilla takes the fallback in 14 regions with non-zero divisors, which is harmless.
- Ruled out (vanilla/16k/20k/24k/30k): multi-part provinces, colour byte edge cases, railways, empty states/regions, neighbour minima, seam contacts, counters.

**Bisect builds for the owner:**
- `EXP-03-24k-fix`: 24,000 provinces with the guard (region 191 divisor −2) → expected to load.
- `EXP-03-div0`: vanilla + 1 province (2166) cut into 3 → region 193 Northern Australia divisor 0 → expected crash at +0x15A4CDC.
- Run fix first, then div0.

**Side finding:** the model flags region 113 in **all EXP-09a–e builds** (symmetric synthetic layout) → predicted crash on load. EXP-09 is withheld from the owner until a follow-up WU (P00b-f4) applies the guard in exp09/synth.

1. No region may take the fallback with a zero divisor (dx or dy). The gate for P05/P07 is `regioncentre.guard_failures` (unsafe **or** seam/unknown without an identical vanilla twin), **not** `unsafe_regions`, which never returns seam regions. Re-check after every province or region change, and keep a ≥1 px margin between the mean and any member-box edge.
2. Prefer regions whose mean point falls inside a member box, so the fallback never runs. Ring-, C- and strip-shaped regions are the ones at risk.
3. Symmetric or regular tilings (grid or strip filler, mirrored regions) are high risk.
4. `validate_map.py` cannot see this. Proposal S12 (owner / plain session; `.claude/**` is frozen for agents): ERROR `REGION_CENTRE_DIV0`, WARN `REGION_CENTRE_FALLBACK`; regions touching the wrap seam use a second rectangle the model doesn't cover yet, so treat them conservatively.
