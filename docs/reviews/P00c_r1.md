## Do not fix (looks odd, is correct)

- **Define namespace** (`zz_exp09_*.lua`). `NDefines_Graphics.NGraphics.*` and `NDefines_Graphics.NFrontend.*` are valid. Vanilla `00_graphics.lua` builds `NDefines_Graphics = { … NGraphics = {…} (l.723; CAMERA_OUTSIDE_MAP_DISTANCE_* l.1184-1185) … NFrontend = {…} (l.1485; CAMERA_MAX_HEIGHT l.1496) }` and ends with `for k,v in pairs( NDefines_Graphics ) do NDefines[k] = v end`. That line copies table references, so `NDefines.NGraphics` and `NDefines_Graphics.NGraphics` are the same table and an assignment through either path lands in it. Workshop evidence (read-only): 239 lines in installed mods use `NDefines_Graphics.N(Graphics|Frontend).*` (e.g. `1826643372/common/defines/eaw_graphics.lua`, `2204739234/common/defines/TWR_mapdefines.lua`). About 208 use `NDefines.N*` (e.g. `2287823948/.../REWORKED_graphics.lua:55` `NDefines.NFrontend.CAMERA_MAX_HEIGHT = 3500`). So the engineer's claim that overrides *must* use `NDefines_Graphics` is too strong, but the chosen form works. `references/11-rendering.md:11` shows the `NDefines.` form. Both are fine, so no change is needed. Neither key appears in `00_defines.lua` or `01_career_profile.lua`. Load order: `00_defines` < `00_graphics` < `01_*` < `zz_*`.
- **`MAP_SIZE_X/Y` inside `pdxwater.shader`.** They are not defined in any `gfx/FX` file and are injected by the engine. The vanilla pixel shader of this same file already uses them (`ApplyIce` l.246, l.262), so the 5120×2304 guard compiles and sees the loaded map. `step( abs(MAP_SIZE_X - 5120.0), 0.5 )` has the correct argument order in both HLSL and GLSL: it returns 1 when the difference is ≤ 0.5. Mixing ints and floats matches vanilla usage (`vPos.y/MAP_SIZE_Y`).
- **z orientation.** The vertex shader sets `VertexOut.pos = float3(x, WATER_HEIGHT, y)` and `uv.y = (y + 0.5 − H)/−H`, so world z = 0 is the bottom (south) row. `Input.pos.xz` is (column, rows counted from the bottom), matching `to_game_xz` (z = H − row). The vanilla `vMapLimitFade` (`vPos.y/MAP_SIZE_Y > 0.74` means north) confirms this. The README's 35.8° N figure is correct: `to_lonlat` of row 599.04 gives 35.76° N.
- **Half-pixel offset.** Texel centres sit at integer world x/z (uv = (x+0.5)/W), while `ee_project` uses continuous pixel edges. The shader outline is therefore shifted about 0.5 px, which cannot be seen against a 40-px band (8-px band for ice). The comment "exact sign" is exact to half a pixel.
- **Equal Earth maths** (checked independently in float32, using the *shader's own literals*). The derivative coefficients are correct: 0.243318 = 3·0.081106, 0.006251 = 7·0.000893, 0.034164 = 9·0.003796. The half-width is `scale·π·cosθ / (M·dfy)`, which is EE x at λ = π. After 3 Newton steps from `y/A1`, the maximum θ error over all 4609 half-rows is 2.2e-7 rad and the maximum half-width error is 6.6e-4 px. The half-width is 2560.0 px at the equator (the lenses meet at the seam) and 1516.7 px at the pole line. `vScale` 945.82563, `vZEquator` 1043.67368, `vYTop` 1.31736276 and `vYBot` −1.08830084 match `Canvas(5120, 2304, 10.9, −60, 90)`. At the east-edge meridian, the shader distance is within 0.002 px of 0 for every latitude from 60° S to 90° N.
- **Wrap.** `frac(x/W)·W` is x − floor(x), in HLSL and in GLSL (`frac` → `fract`, `defines_glsl.fxh:86`), so negative or > W world x from wrapped copies fold correctly. `abs(col − W/2)` is continuous across the seam.
- **Portability and colour-only.** Only `lerp`/`frac`/`saturate`/`step`/`clamp`/`cos` are used, all mapped in `defines_glsl.fxh`. The patch text is ASCII only, has no `[[`/`]]`, and is balanced. Nothing writes to position, uv, depth or alpha: the return alpha `1.0f - waterShore` is untouched and only the RGB of `vOut` changes. The helpers come before `ApplyIce` and use only `cam_distance` (from `standardfuncsgfx.fxh`, which is included). There are no divide-by-zero or NaN paths, since `EE_EqEarthDY` ≥ about 1.13 on the clamped range.
- **Anchors.** Each of the 3 occurs once in vanilla 1.19.3. No patch text contains any anchor, so applying them in order is safe and the order does not matter. All three sit after `MainCode PixelShader`. `water`, `water_no_refractions` and `water_low_gfx` share the one PixelShader, so every graphics setting gets the patch. The committed vanilla text is limited to the three ≤ 41-char anchors and vanilla numbers in comments.
- **Variants.** a is empty. b adds only the outside-map pair (one lever, two keys). c adds `CAMERA_MAX_HEIGHT`. d adds the shader (see the P2 above). Values fall inside vanilla ranges.
- **Invariants, determinism, data loss.** Not applicable: no map data, RNG or geometry is produced by this WU.
