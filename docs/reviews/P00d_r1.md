**Independent re-derivation**
I re-implemented Equal Earth from the Šavrič et al. coefficients, plus the band formula and blend, without importing `ee_project`.
- Forward: on 20k random (λb, r, Δλ, φ) samples the largest difference from `forward_dl` is **1.3e-15**.
- Wrap: for λb 60, 90 and 120 at φ = 0, 45, 89.999, 90 and −60, the one-sided slopes at Δλ = +180 and −180 are equal, and x(±180) = ±X_MAX to 1e-15.
- Blend: g(0) = g′(0) = g″(0) = 0, g(1) = 1 and g″(1) = 0, so the map is C² at λb and across the wrap. At the junction u = r, g′ = k and g″ = 0 on both sides.
- Monotonicity: dx/dλ = c + (X_MAX − w)·g′/(π − λb) ≥ c. The minimum of c is at the poles, where w(90°)/X_MAX = 0.5925, so c > 0 and the map is strictly monotone on every row, poles included.
- Equator: X_MAX − w(0) is exactly 0.0 in float64, so the hybrid is the identity there.
- 60° S: w(−60°)/X_MAX = 0.753. The edge is still reached exactly.

**Area factor equals the E–W stretch**
- y depends on φ only, so ∂y/∂λ = 0 and the Jacobian is triangular. Therefore σ_H/σ_EE = (∂x_H/∂λ)/(∂x_EE/∂λ) = 1 + (X_MAX/w − 1)·π/(π − λb)·g′.
- The numeric Jacobian agrees with the analytic stretch to ≤ 3.9e-8, as given in `report.txt`.

## Do not fix
- **Seam-sensitivity stretch columns are identical for lon0 5.9, 10.9 and 15.9** (Cape Dezhnev 2.102 in all three, and so on). At λb 90 with r 0.5, every seam place lies at |Δλ| ≥ 135°, which is the linear part of the blend (u ≥ r). There g′ = k, so the stretch depends on latitude only. This is correct, just not informative. The land-on-seam counts are the informative columns.
- **The λb 120 / r 0.5 row equals the λb 90 / r 1 row** in the band summary (3.75 at 90° N). Both have kπ/(π − λb) = 4.
- **The hybrid's ω is lower than EE's at Tokyo, Sydney, Lima and other places.** The E–W stretch partly offsets EE's meridian shear at large |Δλ|. I reproduced this independently.
- **`forward()` sends Δλ = −180 (the seam meridian) to the left edge, col 0.0.** Points use `to_pixel`. Geometry that touches the seam must use `forward_dl` / `to_pixel_dl` with unwrapped Δλ, as `render.py` already does.
- **`to_pixel` and `to_pixel_dl` differ by about 1e-14°** because of the rounding in `wrap_lon` (`a + 180 − 180`). This is about 1e-12 px and negligible.
- **The bottom-margin rows, south of 60° S, return valid lon/lat.** `globe_mask()` applies the latitude window, the same as `ee_project`.
- **`roundtrip_error` uses `min(dc, W − dc)`.** This does not hide a wrong-edge return: a pixel coming back on the other edge still shows an error of at least 1 px.
- **`half_width(LATS) <= X_MAX + 1e-15` in the test.** The gap at the equator is exactly 0.0, so the tolerance is harmless.
- **`sys.path.insert(0, EE_SCRIPTS)`.** That folder holds only `ee_project.py` and `validate_map.py`, so nothing is shadowed.
