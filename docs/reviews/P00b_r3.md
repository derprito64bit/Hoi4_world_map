## Verification of the r2 items

### (1) r2 P1: filler lake weather. Fixed.

**Weather source.** `weather_sources` builds `filler_north` from the `88-Bering Sea` block. `with_snow_of` then replaces each period's `snow=` with the value from the same month of `222-Northern Canada`. Only the NW and NE filler regions use it (`exp09.py:306`). The new sea regions keep the unchanged Bering block: `305-…` has 0 lines with `snow=0.600`.

**Syntax.** The built `360-EXP-09 off-globe NE.txt` has 12 `period={}` blocks with the same keys in the same order as vanilla `88-Bering Sea.txt`. The file's braces balance. With every `snow=` value masked, the weather block is string-identical to vanilla 88. The snow values match vanilla 222 month by month: 0.6/0.6/0.3 for Jan–Mar, 0.3 for Apr–Oct, 0.6 for Nov–Dec. `min_snow_level` is untouched: the `\bsnow` regex cannot match inside `min_snow_level`, and `n != 1` is guarded. Month parsing handles two-digit months (`0.10`, `0.11`), and the regex backtracks correctly.

Only a scan of all vanilla regions can say whether the weight combination has a precedent. No vanilla region has `snow>0` and `arctic_water>0` in the same period. The combination is therefore unprecedented, but it is only a pair of weights, so it is not a syntax risk. README reading (2) now covers the case "the engine does not ice lakes".

**The guard is real, in three places:**
- `winter_icy(..., both=True)` requires snow and arctic water, and `tmin < 0`.
- `build` passes `set(lay.off_ids)` as `lakes`.
- `check` passes the new-ID lake mask. That mask equals the filler, because `check` also rejects any new province that is neither a filler lake nor a sea.

**The three negative tests can fail:**
- `no-snow` leaves arctic water at 1.0 and −20 °C.
- `no-arctic-water` leaves snow at 0.6.
- Under the r2 `winter_icy` (snow or arctic water), both of those would pass `check`, so they fail if `both` is dropped or `lakes` is empty.
- `warm` is the r2 test, kept.
- The added precondition assert makes sure the spoil really changes something.
- The unit test also covers `not_icy(..., lakes=...)` directly, and `with_snow_of` raising on a donor that is missing a month.

**Base files identical across a–e.** Checked on the rebuilt output with `diff -rq EXP-09a EXP-09{b..e}`. The only differences are `README.txt`, `descriptor.mod`, `common/` (defines), and `gfx/` for d and e. `--check` compares the shared files byte-for-byte and passes for all five.

## Do not fix (looks odd, is correct)

- **`with_snow_of` parses the month with its own regex instead of reusing `parse_periods`.** Both read the `day.month` start of `between`. Both give 0..11 on vanilla 88 and 222, and the unit test round-trips through `parse_periods`.
- **Summer months of the filler have `snow=0.3` at −20..0 °C.** This is copied from 222 (Apr–Oct 0.3). The experiment needs only Jan–Mar, and year-round cold is inherited from Bering. It is harmless.
- **`check` builds `lakes` from "new-ID lake rows", while `build` uses `lay.off_ids`.** These are the same set. `check` rejects any new province that is not a filler lake or a sea, and the off-globe pixel mask must coincide with those lakes.
- **The README embeds the absolute user-folder path.** Build output is gitignored and machine-local. The same `user_dir` is already used for the error.log path.
- **The EXP-01 SEAM prop text says "about 280 pixels apart if the game wraps".** This is pre-existing text and was not in this delta. r2 measured the minimum wrapped distance at about 248 px, and 280 is a reasonable centroid-level figure for an owner-facing README.
- **The test in `test_install.py` changed from `EXP-01-UK-A` to `EXP-01A`.** This is a strengthening (see (3)), not a weakening.
