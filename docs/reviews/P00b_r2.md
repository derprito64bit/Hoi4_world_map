### r1-01 (P0): ice weather

Weather sources:
- The northern new seas are the tiles whose centroid lies above 50° N. They now take new IDs, and `new_regions` gives them `88-Bering Sea` weather.
- The NW/NE filler also uses `88-Bering Sea` weather. Vanilla 88 is −20..0 °C with `arctic_water=1.000` in all 12 months.
- The southern seas and the SW/SE filler use `32-Southern Ocean` (2..8 °C).
- The built `360-EXP-09 off-globe NE.txt` carries the Bering periods.

The guard is real in three places:
- `weather_sources` fails the build if 88* is not icy.
- `build` raises if any sea or lake within 40 px of either landmark is not `winter_icy`.
- `check` re-parses the build's region files and repeats that test. `test_exp09_check_catches_warm_weather_at_the_ice_landmarks` warms the NE filler and gets the failure.

I also checked `parse_periods` and `winter_icy` against all vanilla regions. Alpine (March snow 0) and Caucasus correctly come out not icy. The parser is sound.

Shader reachability:
- Vanilla `pdxwater.shader` `ApplyIce` uses `vMapLimitFade = saturate(saturate(vPos.y/MAP_SIZE_Y − 0.74)*800)`, with `vPos = Input.pos.xz`, i.e. world z = H − row.
- On 2304 rows, ice therefore needs z > 0.74125·2304 = 1707.8, i.e. row < 596. By `ee_project`, that is **35.9° N** (P00c's 35.8° N is correct).
- Cape Dezhnev projects to row 158.8, col 4365. Cape Prince of Wales projects to row 164.1, col 751. Both are about 435 rows inside the ice zone.
- The ice is also faded by `1 − cam_distance(ICE_CAM_MIN 100, ICE_CAM_MAX 350)`, so ice only shows when zoomed close in. Screenshot 6 correctly says "fully zoomed in".

Variants share the base:
- The `_meta` hashes of b–e differ from a only in README, descriptor, the defines lua files and (d, e) `gfx/FX/pdxwater.shader`.
- The on-disk files of a and e match their `_meta`.
- `shared_files` is cached, `build` refuses a variant file that would overwrite a shared file, and `check` compares every shared file byte-for-byte.
- The negative test flips one heightmap byte and gets "differs from the base shared by all variants".

## Do not fix (looks odd, is correct)

- **Vanilla sea IDs moved south of 50° N in EXP-09.** Northern tiles now take new IDs, so vanilla sea provinces fill row-major tiles below the band. This is intended: the landmarks' surroundings must be under the new cold regions. `check` still verifies that every new ID is in exactly one new region, and the build still passes with the same validator codes. The centroid-versus-`north_row` comparison is deterministic.
- **EXP-09 `check` compares against a freshly rebuilt `shared_files`, not against an independent spec.** For a logic bug in `base()` this is circular. It is not circular for what r1 asked, a stale or different base per variant, and the structural checks earlier in `check` cover the logic.
- **EXP-08 buildings check `break`s on the first bad line and then also reports the multiset mismatch.** This produces two messages for one defect. Harmless.
- **`FROM, TO = PAIRS["UK"]` alias kept in exp01.py.** It is unused but harmless, and keeps imports stable.
- **`test_install.py` still uses `"EXP-01A"` as the ID.** It is only a string that matches `BUILD_ID`, used against a synthetic build root. It is not a stale reference to a real build.
- **SEAM pair centroids use the 0.25·W / 0.75·W thresholds.** This is enough to assert "opposite sides of the seam". The real separation (≈248 px wrapped) is recorded above.
- **Southern regions use 32-Southern Ocean (warm, 2..8 °C).** The shader draws no ice below row 596 (35.9° N) anyway, so southern ice cannot be tested on this canvas. The code comment at `exp09.py:44-45` says so.
