## Do not fix
- **`unsafe` is False for seam regions.** This is intended: `unknown` and `guard_failures` cover them. The code is consistent.
- **Vanilla region 178 with dy 0.** It is a seam region, so it tells us nothing about the dy path. It loads, and it is correctly reported as unknown with a vanilla twin, not as unsafe.
- **EXP-02-300/1200 fail the guard although they loaded.** The guard is conservative on purpose (no new unknown regions), and the docstring discloses it.
- **The twin is looked up by region ID only.** That is stricter than necessary, and fine.
- **The `ids >= len(bx1)` branch cannot be reached through `region_centres`.** It can be reached by calling `region_centre` directly, and the test covers both the out-of-range ID (99) and the ID without pixels (8).
- **`test_guarded_subdivide` now searches for the first `extra` that is unsafe without the guard, instead of a fixed 22.** The search is deterministic and the assertions are unchanged (the plan without the guard gives [2], the guarded plan gives [], and the frozen parent stays whole).
- **`fallback` and `fallback_all` both count 14 in vanilla.** The upper-edge ambiguity does not affect any existing region.
