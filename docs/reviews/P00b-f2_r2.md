## New strategic-region contiguity rule (`exp02b.py:331-358`, `:453-459`)

The rule is sound. `noncontiguous_regions` groups every province in `province_region`: land, sea and lake. `noncontiguous_groups` then unions them over pixel contacts and `adjacencies.csv` links. The state rule was refactored to call the same helper, and it behaves as before: the state counts are unchanged at 8 and 89.

The rule allows only regions that contain a donor (`shrunk`) to become non-contiguous. That is correct, because only donors lose pixels. It also flags any region that *becomes* contiguous, which is a conservative, fail-at-build choice. The `side_effects` region list equals `rc1 - rc0`, and the READMEs print it. The unit test covers both a pixel gap and a link that repairs it.

## Do not fix (looks odd, is correct)

- **The fail line is generic ("compare with the other EXP-02b builds and with EXP-02-1200") and names no build pair.** Together with `ORDER_NOTE` and the per-build neighbour numbers, the owner can tell a 265-neighbour sea failure apart from a 1000-neighbour land failure. The split already removes the confound that round 1 raised.
- **block-400 still combines land and sea in one build.** Its hosts have 87 and 65 neighbours, well below the 800 hosts. The round-1 split recommendation covered block-800 only.
- **The land-800 README lists 40 of 89 states, followed by "...".** `_ids` truncates for readability, and the full list is in `_meta/EXP-02b-block-800-land.json`.
- **"enclaves" counts donors whose every neighbour is a host.** In block-400, a land donor that touches only the sea host would also count. That is the intended meaning ("reachable only through a host").
- **The top-level `info["moved"]` / `info["new_noncontiguous"]` keys are gone.** Nothing outside `exp02b.py` reads them (grep). They now live under `info["effects"]`.
- **`inside_remnant` rebuilds the 400 block with `make_blocks` inside the fixture.** That costs time only. It is module-scoped, and the rebuild is deterministic (byte-identical test).
