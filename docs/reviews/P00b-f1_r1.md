## Safety analysis (what can be deleted or overwritten)

- **Only one destination.** `uninstall` unlinks, and `install` opens for writing, only the `dest` returned by `target_path`. That is `user/mod/` plus a name built from `BUILD_ID`. The regex has no separators, dots or `..`. `target_path` checks that `dest.resolve().parent == moddir.resolve()` and that `mod/` stays inside the user dir. Both checks run before `kit_file_problem`, so the content of `path=` never chooses which file is touched. `path=` is only compared against `want`, so path tricks in the file (`..`, relative paths, junctions, case) can at worst make a file count or not count as the kit's. They cannot redirect the delete.
- **False positive.** For a foreign file to be deleted, it must have the kit's exact file name, a single `path=` resolving to this repo's `build/experiments/<ID>`, and a `name=` with the `P00b <ID> ` prefix. That is the kit's file in every sense that matters. Before this change, main accepted any file containing the marker substring anywhere, so the new predicate is stricter against foreign files, not weaker.
- **Dangling or in-folder symlinks are now refused.** Main checked `dest.exists()`, which is False for a dangling link, so `install` would have followed the link and created the target file. The new code checks `exists() or is_symlink()`, then refuses symlinks. This is an improvement.
- **Parser.** It fails closed:
  - An unterminated quote does not tokenise, so it raises `KitError`.
  - An unbalanced `{` or `}` raises.
  - `key=` with no value raises.
  - A block-valued `name`/`path` gives `None`, which is refused.
  - A duplicate key is refused.
  - A quoted key such as `"path"=` is not recognised, so the file is refused.
  - `name= path="…"` records `name` as `path`, so no `path=` is found and the file is refused.
  - A NUL byte or an over-long path inside `path=` raises during `resolve()`, is caught, and is refused.

  I found no input that is parsed into an accept it should not get.

## Do not fix

- **Path comparison ignores case on Windows.** The `p.resolve() == want` comparison ignores case and slash direction. That is correct here: NTFS is case-insensitive, and the launcher may normalise either.
- **The name check is case-sensitive, and `startswith(prefix + " ")` needs the trailing space.** This is correct. It keeps `EXP-01-UK-A` from matching `EXP-01-UK-AB`, or `EXP-03` from matching `EXP-03-20k`. A case-variant ID on the command line is refused rather than guessed, which fails safe.
- **Relative `path=` is resolved against the user folder.** That is the launcher's convention (`path="mod/…"`), and the value only affects recognition, never the file that is deleted.
- **Files installed by the old `install.py` are still recognised.** They carry `# generated by …` and have not yet been rewritten by the launcher, but comments are skipped, and those files have the same `name=` and `path=`.
- **`uninstall` refuses when the repo has moved or is run from another worktree** (`path=` points at a different `build/experiments`). This is intended. The message names both paths, so the owner can delete the file by hand.
- **The removed `MARKER` and the changed first test.** `assert inst.MARKER in text` was replaced by `"#" not in text` plus `is_kit_file(...)`. This follows the new design and is not a weakened assertion. No test was deleted or skipped.
- **The `texts.py` note.** `ud` is in scope, and the note now correctly says that the launcher's rewrite is harmless.
