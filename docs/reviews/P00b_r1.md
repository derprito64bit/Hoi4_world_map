## Hard constraints — verdicts

- **(a) One property per experiment.** Met. Each README names the property. EXP-03-20k carries the 6/7/8-px provinces, which is the allowed exception. The reported side effects:
  - **EXP-08, 22 Arctic provinces became coastal, plus new seas/regions.** These follow from invariant 5 once ocean is placed above land that already touches the top edge. New sea provinces need regions, weather, localisation and unit stacks (invariant 9), and newly coastal land needs positions. None of this is a second property. It is consistency, and the README states it. Padding with lakes instead would pull in EXP-06's question, so ocean is the right choice. → Do not fix.
  - **EXP-06, unit-stack lines removed for the converted provinces.** This is part of "write them as lakes": 124 of 126 vanilla lakes have none. → Do not fix. The kept `naval_terrain`, however, is an avoidable extra (P2 above).
  - **EXP-02, crossed provinces end up in two parts.** This is unavoidable for any strip that crosses other provinces. Multi-part provinces are baseline: 488 in vanilla. Contacts, coast flags, positions and the `STATE_NONCONTIGUOUS` count (30) are unchanged. → Do not fix. The 1-px thinness is the real confound (P2 above).
  - **EXP-09, 1-2 sea pixels at the seam.** A 2×2 block across the wrap seam with off-globe above sea on both sides cannot be fixed within one class without a province straddling the seam. The pixels are recorded, `check` caps them at 4 on column W-1, and they are invisible. → Do not fix.
- **(b) Validator passes except for the tested property.** Met; see the JSONs above. EXP-05 and the EXP-09 shader/define variants have no validator-visible property, and this is documented.
- **(c) Nothing from the game folder is committed.** Met. The diff contains only code and tests. Vanilla bytes go only to `build/`. The test fixtures use synthetic text. P00c's anchors are P00c's matter and were already reviewed.
- **(d) install.py containment.** Met.
  - Only `mod/p00b_<ID>.mod` is ever written or deleted.
  - The ID regex rejects `..`, `\`, drive letters and empty IDs.
  - `mod` resolving elsewhere (symlink or junction) is refused, and this is tested with a junction fallback on Windows. A broken symlink falls through to the `is_within(dest, user)` refusal.
  - Path comparison uses `resolve()` plus `WindowsPath` equality, which is case-insensitive.
  - `--uninstall` deletes only a file that carries the kit marker, and it leaves foreign files alone (tested).
  - Remaining gap: no sanity check that the env var is a HOI4 user dir (P2).
- **(e) `--check` is real.** Real and strict for EXP-01, 02, 03, 05, 06 and 07. It recomputes coastal flags, refinement, X-crossings and exact line diffs. It is weaker for EXP-08 and EXP-09 (P1 above).

## Do not fix (looks odd, is correct)

- **EXP-01 row placement and format.** The row goes directly before vanilla's `-1;-1;;-1;-1;-1;-1;-1;-1 ` terminator, which keeps its trailing space. The trailing `#Start province ID;…` comment line and blank lines stay byte-identical, and the file uses LF like vanilla. Variant A's `ADJ_THROUGH` ERROR is the validator knowing only the canal pattern (Kiel, Suez and Panama are sea-sea `sea` rows with a *land* Through). It is expected.
- **EXP-03 file set.** `definition.csv` rows are appended contiguously, and `Definition.parse` enforces `rows[i][0]==i`. Only the coastal column of vanilla rows changes. Children join their parent's state *and* region, so no state spans two regions. Railways are repaired only through the split family (`check` re-verifies adjacency, including `adjacencies.csv` links). `supply_nodes`, `weatherpositions` and `adjacencies` stay vanilla because every parent keeps its ID on the piece holding its naval-base spawn or centre.
- **`floating_harbor` column 7 = the land province itself.** This matches vanilla (e.g. `12;floating_harbor;…;9317`, where 9317 is land). The kit writes the coastal set for every coastal member, while vanilla has 2,334 floating harbours against 2,362 other coastal lines: a harmless superset. The per-province types (`bunker`, `supply_node`, `special_project_facility_spawn`; coastal: `naval_base_spawn`, `coastal_bunker`, `naval_supply_hub`, `naval_headquarters`, `floating_harbor`) match the 1.19.3 counts (10,154 / 2,362).
- **EXP-07 replace_path.**
  - Safe: all 1,081 state files are shipped (1,080 byte-identical) and no DLC ships state history.
  - `map/supplyareas` does not mention 1081, and province 1081 (Korea) in railways and unitstacks is untouched.
  - The script scan fails loudly on any unknown reference kind, and `test_exp07_finds_all_script_references` passes.
  - Renaming the file forces `replace_path`: without it, vanilla's `1081-Otago.txt` would also load.
  - The gap is 1081-1082 because the last state became max+2. That is what the prompt asks for, and it still counts as one gap.
- **EXP-08 DDS.**
  - All paddings are block-aligned: 256/128/64 texels for colormap/_0, _1 and _2.
  - The mip count is recomputed as `bit_length(max(w,h))`, which is 12 for both 3072×1280 and 2816×1280.
  - Only height, width, pitch/linear size and mip count change in the header. `DDSD_LINEARSIZE` files get `level_size` and the BGRA colormap gets `width*4`.
  - The flags, caps and pixel format stay vanilla.
- **BMP I/O.** It keeps the vanilla header bytes (V5 124-byte DIB, the 256-entry palette on trees and the palette on terrain). It rewrites only the size fields and preserves the 2 trailing bytes where vanilla has them. It rejects compressed and 32-bit input.
- **EXP-05.** Nearest-neighbour resampling cannot create new palette indices. Height stays 600. It is a clean single-axis scale test.
- **Determinism.** The k-means uses farthest-point initialisation with sorted ties. `new_colors` is seeded. All dict and set iteration goes through `sorted`, and tiling is labelled row-major. `test_small_builds_are_byte_identical` and the unit determinism tests pass. The README contains the machine's user path, but builds are not committed or compared.
- **Performance.** The slowest build is EXP-03-30k at 20.8 s, and the full `--check` takes under 1 min. Well inside the limit.
- **Texts.** `CANNOT_PROVE` is verbatim from the to-check file, `test_texts` keeps it in sync, and every README ends with it (EXP-03-20k lists EXP-03 and EXP-04).
- **Screenshot 6.** The EXP-09 screenshot 6 wording (Cape Dezhnev / Cape Prince of Wales, fully zoomed in, both sides, ragged ice edge) follows the P00c r2 P2 correctly. Once P0 is fixed it is right, and the landmarks sit 6 px inside the outline (Dezhnev col 4365, edge at 4371 on row 159).
